# Plan scope review

Before the plan is written, decide **deliberately** what scope the work should have. A
plan written without this choice drifts to whatever was easiest to write; a scope review
chooses the ambition up front.

Run it in the idea/planning stage. Pick ONE mode, state it, and plan accordingly.

## The four scope modes

| Mode | What it does | Use when |
|---|---|---|
| **SCOPE EXPANSION** | Dream big: rethink the problem, find the 10x version, challenge premises, grow the surface to the ambitious whole | The problem is worth solving and the current plan under-serves the opportunity |
| **SELECTIVE EXPANSION** | Hold the core scope, cherry-pick the highest-leverage expansions only | A good core exists; add the few pieces that multiply its value |
| **HOLD SCOPE** | Maximum rigor: no growth, nail exactly the declared scope | Scope is already right / constrained by time or dependencies |
| **SCOPE REDUCTION** | Strip to essentials; cut anything not load-bearing for the core outcome | The plan is bloated, or the narrowest valuable slice is what should ship |

## Rules

- **The mode is a decision, not a default.** State it explicitly and record it (in the plan
  or an ADR). "Let me just hold scope" without saying so is not a scope review.
- SCOPE EXPANSION must still produce a shippable first slice — expanding the *vision* never
  excuses skipping a narrow wedge to land today.
- Challenge premises in the mode: if the mode expands, challenge the "why not bigger";
  if it reduces, challenge "why is this necessary". The challenge is the review.
